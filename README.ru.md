# agent-tasks

[English version](README.md)

Агенты-программисты вроде Claude Code и Codex между сессиями всё забывают: согласованный план,
что уже сделано, почему выбрали так, а не иначе. Настоящая работа к тому же идёт в нескольких
репозиториях и на нескольких машинах. А план агента в чате неудобно ревьюить: на строку не
укажешь, и каждая новая версия хоронит предыдущую.

agent-tasks держит эту работу вне конкретного репозитория. Это небольшой сервер, который вы
поднимаете у себя. Агенты подключаются к нему по MCP: пишут планы и заметки документами,
отмечают выполненные шаги и ведут журнал, по которому потом продолжают работу. Вы, то есть
человек, на которого работает агент, читаете эти документы в браузере и комментируете
выделенный текст, примерно как в ревью pull request. Агент забирает ваше ревью и отвечает на
каждый комментарий.

Сервер устроен просто: один бинарник на Go, файл SQLite и встроенный веб-интерфейс. К нему
прилагается совместимый с Claude Code и Codex плагин: скиллы и хук начала сессии, которые
учат агентов с ним работать.

## Основные понятия

- **Задача.** Единица работы: название, статус (`active`, `waiting`, `later`, `archived`),
  свободные теги (`topic:…`, `area:…`) и места, где идёт работа. Идентификаторы вида `T-12`.
- **Документ и ревизия.** Markdown-документы задачи: план, исследование, заметки. Каждое
  сохранение создаёт новую ревизию, старые не меняются. Любые две можно сравнить и к любой
  старой вернуться.
- **Раунд ревью и комментарий.** Ваши комментарии к одной ревизии: к выделенному тексту или ко
  всему документу. Они копятся в черновике и уходят агенту разом. Агент отвечает, закрывает их
  и пишет следующую ревизию. Если прокомментированного текста больше нет, комментарий остаётся
  с пометкой «устарел».
- **Пункт плана.** Каждая строка `- [ ]` в документе. Пункт сохраняет идентификатор от ревизии
  к ревизии. Отметить его и добавить заметку можете и вы, и агент, документ при этом не
  переписывается.
- **Журнал.** Короткие записи агента. *Контекст*: где сейчас работа, чтобы новая сессия
  подхватила. *Сделано*: что сделали. *Решение*: что решили и почему.
- **Место.** Где идёт работа. Git-репозиторий, который узнаётся по remote `origin` (на всех
  машинах одинаково), или локальная папка. Сервер запоминает, где каждое место лежит на каждой
  вашей машине.
- **Дело.** Заметка в одну строку на потом (`D-7`), к задаче не привязана. Несколько дел можно
  превратить в задачу.
- **Рабочая папка.** `<workspace_root>/<id задачи>` на диске: черновики агента, скрипты,
  выгрузки. Так они не попадают в ваши репозитории. Если работаете на нескольких машинах,
  синхронизируйте её любым инструментом синхронизации файлов.

## Как проходит задача

1. Вы описываете работу. Агент со скиллом `plan` читает код и задаёт вопросы пачками, пока все
   развилки не решены.
2. Он заводит задачу, пишет план документом и присылает ссылку.
3. Вы открываете ссылку, комментируете выделенный текст, добавляете общие замечания и
   отправляете ревью.
4. Агент отвечает на каждый комментарий, пишет следующую ревизию и отмечает раунд отработанным.
   Так повторяется, пока вы не скажете «делай».
5. Агент идёт по плану: отмечает пункты, пишет заметки, ведёт журнал. Следующая сессия, хоть на
   другой машине, продолжит с того места, где остановилась прошлая.
6. Когда работа закончена, задача уходит в архив. Архивные задачи удаляются через заданный
   срок.

Начать можно двумя путями. **Из репозитория**: при открытии сессии хук покажет задачи и дела
этого репозитория. **Из папки задачи**: откройте рабочую папку задачи, и хук покажет эту
задачу вместе с путями к её репозиториям на этой машине.

Идеи, до которых руки ещё не дошли, записываются в дела («запиши в дела: …»). Потом выбираете
несколько в вебе и делаете из них задачу.

## Быстрый старт

### 1. Запуск сервера

Создайте файл токенов, по одному `имя=секрет` на строку. Имена попадают в логи, секреты нет.

```sh
mkdir -p ~/.config/agent-tasks
printf 'laptop=%s\n' "$(head -c 24 /dev/urandom | base64 | tr -d '/+=')" > ~/.config/agent-tasks/tokens
chmod 644 ~/.config/agent-tasks/tokens     # контейнер работает от uid 10001
```

Запустите образ (или соберите свой: `docker build -t agent-tasks .`):

```sh
docker run -d --name agent-tasks -p 127.0.0.1:8080:8080 \
  -v agent-tasks-data:/data \
  -v ~/.config/agent-tasks/tokens:/run/tokens:ro -e AGENT_TASKS_TOKENS_FILE=/run/tokens \
  ghcr.io/svesh87/agent-tasks:<tag>
```

Или скачайте бинарник из релиза и запустите
`AGENT_TASKS_TOKENS_FILE=~/.config/agent-tasks/tokens ./agent-tasks serve`.

Откройте <http://localhost:8080>. Своего входа у веба нет, поэтому держите его на localhost
или за прокси с авторизацией (см. ниже).

### 2. Подключение Claude Code

```sh
claude plugin marketplace add https://github.com/svesh87/agent-tasks
claude plugin install agent-tasks@agent-tasks
claude mcp add --transport http --scope user agent-tasks http://localhost:8080/mcp \
  --header "Authorization: Bearer <секрет>"
```

Для хука начала сессии создайте `~/.config/agent-tasks/config`:

```ini
url = http://localhost:8080
token = <секрет>
```

### 3. Подключение Codex

Установите плагин из маркетплейса этой репы:

```sh
codex plugin marketplace add https://github.com/svesh87/agent-tasks
codex plugin add agent-tasks@agent-tasks
```

Подключите MCP-сервер:

```toml
# ~/.codex/config.toml
[mcp_servers.agent-tasks]
url = "http://localhost:8080/mcp"
bearer_token_env_var = "AGENT_TASKS_TOKEN"
tool_timeout_sec = 330
```

Хук `SessionStart` использует тот же конфиг, что и в Claude Code:

```ini
# ~/.config/agent-tasks/config
url = http://localhost:8080
token = <секрет>
```

Обновите плагин и проверьте установку:

```sh
codex plugin marketplace upgrade agent-tasks
codex plugin list
```

После установки или обновления откройте новую сессию Codex. Выполните `/hooks`, проверьте хук
плагина и доверьте его, когда Codex попросит: доверие привязано к текущему хешу хука.

### За прокси с авторизацией

Чтобы сервер был доступен с нескольких машин, поставьте перед ним прокси, который отвечает за
вход. Например, Cloudflare Access:

- Одно приложение для веба, где входят люди. Запустите сервер с
  `-web-auth-header Cf-Access-Authenticated-User-Email`, чтобы он отклонял запросы в обход
  прокси, и с `-base-url https://tasks.example.com`, чтобы ссылки вели на публичное имя.
- Второе для `/mcp` и `/hooks/*`, с доступом по сервисным токенам. Агенты отправляют заголовки
  токена вместе с bearer-токеном сервера.
- Прокси обрывают запросы, которые молчат около 100 секунд, поэтому ограничьте долгое ожидание:
  `-review-wait-max 90`.

Claude Code (`claude mcp add-json agent-tasks '<json>'` или `.mcp.json`; `${VAR}` берётся из
окружения, `timeout` в миллисекундах):

```json
{
  "type": "http",
  "url": "https://tasks.example.com/mcp",
  "headers": {
    "Authorization": "Bearer ${AGENT_TASKS_TOKEN}",
    "CF-Access-Client-Id": "${CF_ACCESS_CLIENT_ID}",
    "CF-Access-Client-Secret": "${CF_ACCESS_CLIENT_SECRET}"
  },
  "timeout": 120000
}
```

Codex:

```toml
[mcp_servers.agent-tasks]
url = "https://tasks.example.com/mcp"
bearer_token_env_var = "AGENT_TASKS_TOKEN"
env_http_headers = { "CF-Access-Client-Id" = "CF_ACCESS_CLIENT_ID", "CF-Access-Client-Secret" = "CF_ACCESS_CLIENT_SECRET" }
tool_timeout_sec = 120
```

Хук: добавьте те же заголовки в `~/.config/agent-tasks/config`:

```ini
header = CF-Access-Client-Id: <id>
header = CF-Access-Client-Secret: <секрет>
```

## Веб-интерфейс

- **Поиск** по задачам, документам, комментариям, итогам ревью, журналу и делам, с учётом
  словоформ, русских и английских. У каждого результата видно, что совпало, и он открывается
  сразу на месте: документ на нужной ревизии с подсветкой, комментарий, запись журнала.
- **Задачи**: фильтры по статусу, месту и тегам; смена статуса у нескольких задач разом;
  переименование и правка описания прямо на странице; пути к каждому месту на всех машинах.
- **Документы**: комментарии к выделенному тексту, отправка раунда ревью, ответы. Отметки и
  заметки к пунктам плана, причём видно, кто отметил: вы или агент. Правка последней ревизии в
  markdown с предпросмотром; если тем временем появилась новая ревизия, вы об этом узнаете и
  ничего не перезапишется. История, сравнение ревизий, возврат к старой.
- **Дела**: быстрое добавление, места и теги с подсказками, массовые «сделано», «отбросить» и
  «вернуть», задача из нескольких дел.
- Английский и русский, светлая и тёмная тема, работает на телефоне.

## Настройки

| Флаг | Переменная окружения | По умолчанию |
|---|---|---|
| `-listen` | `AGENT_TASKS_LISTEN` | `:8080` |
| `-db` | `AGENT_TASKS_DB` | `agent-tasks.db` (в образе `/data/agent-tasks.db`) |
| `-base-url` | `AGENT_TASKS_BASE_URL` | `http://localhost:8080` |
| `-tokens-file` | `AGENT_TASKS_TOKENS_FILE` | нет (по `имя=секрет` на строку) |
| нет | `AGENT_TASKS_TOKENS` | нет (`имя=секрет,имя2=секрет2`) |
| `-retention-days` | `AGENT_TASKS_RETENTION_DAYS` | `90` (`0` хранит архив вечно) |
| `-review-wait-max` | `AGENT_TASKS_REVIEW_WAIT_MAX` | `900` секунд |
| `-workspace-root` | `AGENT_TASKS_WORKSPACE_ROOT` | `~/agent-work` |
| `-web-auth-header` | `AGENT_TASKS_WEB_AUTH_HEADER` | нет (без проверки) |

Токены флагами не принимаются. Бэкапы, экспорт в markdown и устройство сервера описаны в
[docs/backend-design.md](docs/backend-design.md), общие правила для сервера и скиллов лежат в
[CONTRACT.md](CONTRACT.md).

## Скиллы и хук начала сессии

Эта репа служит совместимым с Claude Code и Codex маркетплейсом с одним плагином
`agent-tasks` (`plugins/agent-tasks/`). Скиллы пользуются только MCP-инструментами этого
сервера:

- `plan`: разобраться в задаче, расспросить, написать план, доработать после ревью, начать по
  вашему «делай»;
- `task`: найти, продолжить, отложить или закрыть задачу; показать задачи и дела текущего
  репозитория;
- `review`: забрать отправленный раунд и ответить на каждый комментарий;
- `todo`: записать, показать и закрыть дела.

Хук `SessionStart` работает в Claude Code и Codex: срабатывает при старте сессии, её
продолжении и после сжатия контекста и выводит задачи и открытые дела текущего места.
Настройки он берёт из
`~/.config/agent-tasks/config` (`url`, `token`, `machine` и сколько угодно строк
`header = Имя: значение`) или из окружения (`AGENT_TASKS_URL`, `AGENT_TASKS_TOKEN`,
`AGENT_TASKS_MACHINE`, `AGENT_TASKS_HEADERS`, `AGENT_TASKS_HEADERS_FILE`). Имя машины по
умолчанию берётся из короткого имени хоста; в контейнерах, где имя хоста случайное, задайте его
явно. Секреты хук передаёт `curl` через stdin, а не в командной строке. Без настроек или при
недоступном сервере он молчит.

## Разработка

```sh
cd web && npm ci
npm run dev                                          # интерфейс на тестовых данных, http://localhost:5173
AGENT_TASKS_API=http://127.0.0.1:8080 npm run dev    # интерфейс против запущенного сервера
npm run build                                        # web/dist, его встраивает Docker-сборка
npm run build:single                                 # демо одним файлом на тестовых данных

# проверки Go без локального Go (из корня репы)
docker run --rm -v "$PWD":/src -w /src -e CGO_ENABLED=0 golang:1.27.2-alpine3.24 \
  sh -c 'go vet ./... && go test ./...'

sh plugins/agent-tasks/tests/session-context-test.sh  # хук; нужны curl, git, python3
```
